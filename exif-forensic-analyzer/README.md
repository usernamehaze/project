# EXIF Forensic & Scam-Image Analyzer

A digital-forensics tool for images: extracts and audits EXIF/metadata for
tamper indicators, OCRs any text rendered inside the image (e.g. a
screenshotted SMS/email), and decodes any QR codes present — routing both
the OCR'd text and QR-decoded URLs through risk analysis, including the
SMS phishing classifier from the sibling [`../`](../README.md) project.

## Why this project

This is the second, more forensics-forward half of the pair. The [SMS
phishing detector](../README.md) is a classification problem: given text,
is it a scam? This tool is closer to what a digital forensics
investigation of a *reported* scam actually starts with — someone hands you
a screenshot, and the first questions are: where did this image actually
come from, has it been altered, and does its content check out. EXIF/
metadata analysis is the standard first step for that, which is why it was
the top idea in the original recommendation list for this niche.

It also demonstrates something the classification project alone couldn't:
building one component that *consumes* another. The scam-image path here
doesn't reimplement text classification — it OCRs the image and hands the
extracted text to the already-trained model in `../src/predict.py`. QR-code
URLs get their own risk analysis, reusing `../src/features.py`'s
`SCAM_BRAND_KEYWORDS` list so "does this domain impersonate GCash/PayPal/
etc." isn't a second, drifting copy of that list.

## What it does

**Metadata forensics** (`forensics/metadata_extractor.py`):
- EXIF extraction: camera make/model, capture/digitized/modified
  timestamps, software tag, GPS coordinates, embedded thumbnail.
- File hashing (MD5 + SHA256) for a basic chain-of-custody record.
- Tamper-indicator flags, each reported with an explicit note on what it
  does and doesn't prove:
  - `no_exif_data` — no EXIF block at all (informational: normal for
    screenshots/PNGs/re-saved images, not proof of anything)
  - `editing_software_present` — Software tag names an editor (Photoshop,
    GIMP, Snapseed, etc.)
  - `modify_date_after_capture_date` — the file's modify timestamp is >24h
    after its capture timestamp
  - `gps_present` — informational privacy flag, not a tamper indicator
  - `thumbnail_mismatch` — the embedded EXIF thumbnail (generated at
    capture/edit time) is perceptually very different from the main image,
    via a simple 8×8 average-hash comparison — a classic sign the main
    image was swapped or heavily edited after the thumbnail was made, or
    that metadata was copied from an unrelated file

**Scam-image detection**:
- OCR (`forensics/ocr.py`, via Tesseract) extracts any text rendered in the
  image, then `forensics/scam_bridge.py` classifies it with the sibling
  project's trained phishing model.
- QR decoding (`forensics/qr_scanner.py`, via pyzbar) extracts any QR
  payload; if it's a URL, `analyze_url()` scores it for shorteners, raw-IP
  hosts, scam-associated TLDs (`.info`, `.xyz`, `.top`, ...), hyphen-heavy
  generated-looking domains, and brand impersonation (domain mentions a
  known brand — `gcash`, `paypal`, `irs`, ... — but isn't that brand's real
  domain).

**Report** (`forensics/report.py` + `forensics/cli.py`): combines all of
the above per image into one verdict. Deliberately, `no_exif_data` and
`gps_present` do *not* by themselves trip the headline "FLAGGED" verdict —
see "What didn't work" below for why that took a second pass to get right.

## Verified results (real output, not illustrative)

Run against the 8 synthetic fixtures in `tests/fixtures/` (generated by
`scripts/generate_test_fixtures.py` — no real photos, no real scam
infrastructure):

| Fixture | Overall verdict |
|---|---|
| `clean_photo.jpg` (consistent EXIF, matching thumbnail) | no scam/tamper signals detected |
| `edited_photo.jpg` (Photoshop tag, stale modify date) | FLAGGED: `editing_software_present`, `modify_date_after_capture_date` |
| `mismatched_thumbnail_photo.jpg` (thumbnail ≠ main image) | FLAGGED: `thumbnail_mismatch` |
| `stripped_screenshot.png` (no EXIF, no text) | no scam/tamper signals detected |
| `legit_screenshot.png` (casual text) | no scam/tamper signals detected (OCR text classified HAM) |
| `phishing_screenshot.png` (fake GCash SMS screenshot) | FLAGGED: OCR text classified SPAM (p=0.99) |
| `qr_phishing.png` (`gcash-verify-account.info`) | FLAGGED: QR URL `high_risk`, score 65/100 |
| `qr_legit.png` (`wikipedia.org`) | no scam/tamper signals detected |

17/17 tests pass (`python -m pytest tests/ -v`), covering metadata
extraction, QR decoding/URL risk scoring, and the full end-to-end report.

## What didn't work (and why)

- **The overall "FLAGGED" verdict was too noisy at first.** Early on, *any*
  non-empty red-flag list (including just `no_exif_data` or `gps_present`)
  marked the image "FLAGGED" — which meant every screenshot and every QR
  code image (neither of which normally carries EXIF) got flagged, drowning
  out the actually-interesting cases. Fixed by splitting flags into
  informational-only (`no_exif_data`, `gps_present` — surfaced, but don't
  drive the verdict) versus notable (`editing_software_present`,
  `modify_date_after_capture_date`, `thumbnail_mismatch`, a spam
  classification, a high/medium-risk QR URL). `test_legit_screenshot_not_flagged`
  and `test_qr_legit_not_flagged` pin this down.
- **`analyze_url()` had a real bug that a test caught, not code review**:
  `urlparse("http://just some plain text").netloc` returns a non-empty
  string (`"just some plain text"`) because `urlparse` doesn't validate
  hostnames — it just splits on delimiters. That meant *any* plain text
  with no `/` in it was scored as a URL. Fixed with an actual hostname
  regex (plus an IP-address check) in a new `is_url()` function, and
  `report.py`'s duplicate, equally-broken `_looks_like_url()` was deleted
  in favor of calling the fixed, tested version. `test_non_url_returns_not_a_url`
  covers this.
- **Perceptual-hash threshold for `thumbnail_mismatch` was picked
  empirically, not derived**: 20/64 bits of an 8×8 average hash. This
  worked cleanly on the synthetic fixtures (a same-image thumbnail scores
  ~0-5, a genuinely different image scores 24+), but real-world thumbnails
  from actual cameras/phones will have more natural variation (different
  compression, slight crops) than these synthetic tests exercise, so this
  threshold is a starting point, not a validated constant.

## Limitations

- The scam-image path only works when text is legible enough for Tesseract
  to OCR cleanly — low-resolution, rotated, or stylized-font screenshots
  will produce garbled text and an unreliable classification.
- Metadata forensics only covers EXIF (JPEG/TIFF-style). PDFs, Office
  documents, and video files carry their own metadata formats not handled
  here.
- `thumbnail_mismatch` and the informational/notable flag split are backed
  by 8 synthetic fixtures, not a real-world tampered-image dataset — the
  detection *logic* is sound (standard forensic technique) but its
  thresholds haven't been validated against real edited photos at scale.
- Brand-impersonation detection in `qr_scanner.py` only has canonical
  domains for a handful of major brands (`CANONICAL_DOMAINS`); most brands
  in `SCAM_BRAND_KEYWORDS` fall back to a weaker "mentions a scam-associated
  term" signal rather than a real impersonation check.
- This tool flags signals for a human to review — it does not make a legal
  or definitive determination of fraud or tampering, and none of its flags
  should be read as one.

## Project structure

```
forensics/metadata_extractor.py   EXIF extraction, hashing, tamper-flag detection
forensics/ocr.py                  Tesseract OCR wrapper
forensics/qr_scanner.py           QR decoding + URL risk scoring (reuses ../src/features.py)
forensics/scam_bridge.py          routes OCR'd text through ../src/predict.py's trained model
forensics/report.py               combines everything into one per-image report
forensics/cli.py                  CLI entrypoint
scripts/generate_test_fixtures.py regenerates the 8 synthetic test images
tests/fixtures/                   the generated test images
tests/                            pytest suite (17 tests)
```

## How to run

Requires the sibling project's trained model to exist at `../models/`
(already committed — see the [phishing detector README](../README.md) if
you need to retrain it) for the scam-classification path; metadata-only
analysis works without it.

```bash
# system dependencies (Debian/Ubuntu)
apt-get install -y tesseract-ocr libzbar0

pip install -r requirements.txt

# regenerate the test fixtures (optional, already committed)
python3 scripts/generate_test_fixtures.py

# analyze an image
python3 -m forensics.cli path/to/image.jpg
python3 -m forensics.cli path/to/image.jpg --json

# run tests
python3 -m pytest tests/ -v
```
