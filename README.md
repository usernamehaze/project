# Phishing / Smishing SMS Detector (Philippines + International scam patterns)

A text classifier that flags phishing/smishing SMS messages, combining a
general spam dataset with two hand-curated sets of region-specific scam
patterns: one for the Philippines (GCash/PayMaya account-lock phishing,
fake courier COD fees, SIM registration scams, lotto/raffle scams) and one
for common international patterns (USPS/FedEx/DHL parcel fees, PayPal/
Chase/Barclays bank alerts, IRS/HMRC tax scams, E-ZPass/toll-road smishing,
fake Netflix/Apple ID renewals).

## Why this project

Crime documentaries got me interested in how digital evidence and fraud
actually get investigated, and that pulled me toward cybersecurity and
digital forensics specifically, on top of a general interest in AI/ML. This
project sits at the intersection of both: it's a real ML classification
problem (feature engineering, model comparison, error analysis) applied to
a fraud/security use case I can evaluate critically rather than take on
faith.

It started as a Philippines-specific project, because public spam datasets
are almost all UK/US English SMS and miss the smishing that actually
circulates here entirely (GCash/PayMaya, Globe/Smart, local banks, LBC/J&T,
government agencies like the NTC, all in Taglish). I then generalized it:
the same gap exists everywhere — a US/UK model trained only on that public
dataset has never seen an E-ZPass toll scam or a Barclays phishing text
either, because those datasets are themselves years out of date. So the
project now treats "region-specific scam vocabulary" as the thing to solve
generally, with the Philippines as the first, most-developed case study
rather than the whole scope.

## Dataset

- **[UCI SMS Spam Collection](https://archive.ics.uci.edu/dataset/228/sms+spam+collection)**
  (Tiago A. Almeida & José María Gómez Hidalgo, public/research use)
  — 5,574 labeled English SMS messages (`data/raw/sms_spam_collection.tsv`),
  mostly UK, mid-2000s.
- **PH scam augmentation set** (`data/raw/ph_scam_augmentation.csv`,
  generated by `scripts/build_ph_augmentation_dataset.py`) — 95 messages
  (55 spam / 40 ham) I wrote from scratch, modeled on publicly reported
  scam formats (BSP/NTC/DICT consumer advisories, GCash's own scam-awareness
  posts, news coverage).
- **International scam augmentation set**
  (`data/raw/international_scam_augmentation.csv`, generated by
  `scripts/build_international_augmentation_dataset.py`) — 82 messages
  (48 spam / 34 ham) covering US/UK/EU/AU/CA patterns: parcel-fee scams
  (USPS, FedEx, DHL, Royal Mail, Evri, Canada Post, Australia Post), bank/
  payment-app phishing (PayPal, Venmo, Chase, Barclays, HSBC, Revolut),
  telco billing scams (AT&T, Verizon, Vodafone), tax-authority impersonation
  (IRS, HMRC), toll-road smishing (E-ZPass, FasTrak, SunPass — a large
  current wave in the US), and subscription/tech phishing (Netflix, Apple
  ID, Coinbase, WhatsApp).

Both augmentation sets are entirely synthetic — written from scratch to
mirror publicly reported scam *templates*, with no real phone numbers,
accounts, or working links. Both also deliberately include
*legitimate-looking* messages from the same brands (a real GCash receipt, a
real Amazon shipping notice), so the model can't shortcut to "mentions
GCash/PayPal → spam"; it has to learn the actual signal (urgency + a link +
a request for credentials, not just the brand name).

After combining and de-duplicating, the working dataset is **5,335
messages** (14.0% spam) — still meaningfully imbalanced, which is why F1 on
the spam class (not accuracy) is the metric that matters here.

## Approach

**Features** (`src/features.py`):
- TF-IDF, word-level, 1-2 grams (10,572 features)
- TF-IDF, character-level, 3-5 grams (23,055 features) — catches obfuscated
  spelling (`fr33 l0ad`, spaced-out brand names) that word tokenization misses
- 12 handcrafted signals: has a URL / shortened URL, digit ratio, uppercase
  ratio, "SHOUTING" word count, exclamation count, money-amount mentions
  (₱/$/£/€), a country-agnostic phone-number pattern, count of urgency
  phrases (`verify`, `suspended`, `claim now`, ...), and count of scam
  brand/keyword matches spanning both regions (`gcash`, `otp`, `ntc`, `usps`,
  `paypal`, `irs`, `e-zpass`, ...). Keyword matching is word-boundary-aware
  (`\bups\b`, not a bare substring check) so short brand tokens like "ups"
  don't fire on unrelated words like "backups".

**Models compared** via 5-fold stratified cross-validation on the training
split (`src/train.py`), scored on F1 for the spam class:

| Model | CV F1 (spam) |
|---|---|
| Naive Bayes | 0.939 |
| **Logistic Regression** | **0.952** |
| Linear SVM | 0.950 |

Logistic Regression won and was refit on the full training set (80/20
stratified split, seed 42).

**Held-out test set** (1,067 messages, never seen during training or model
selection):

| | precision | recall | f1 |
|---|---|---|---|
| ham | 0.993 | 0.998 | 0.996 |
| spam | 0.986 | 0.960 | 0.973 |

Confusion matrix: **TN=916, FP=2, FN=6, TP=143** — 2 legitimate messages
flagged as spam, 6 phishing/spam messages missed, out of 1,067.

Run `python -m src.evaluate` to reproduce this and see the actual
misclassified messages, not just the numbers.

## What didn't work (and why)

- **Naive Bayes collapsed to F1 ≈ 0.17** the first time I combined TF-IDF
  with the handcrafted features, despite doing fine (F1 ≈ 0.82) on TF-IDF
  alone. MultinomialNB assumes count-like features on a roughly consistent
  scale; mixing in raw, unbounded values like message `length` (up to ~500)
  alongside 0-1-ish TF-IDF weights violates that assumption outright and
  wrecks its probability estimates.
- **LinearSVC failed to converge** (`ConvergenceWarning`) even at
  `max_iter=5000`, for the same underlying reason — a few large-magnitude
  handcrafted features dominated the optimization landscape.
- **Fix**: `MaxAbsScaler` on the full concatenated feature matrix (train-fit,
  applied to test) before any model sees it. This is sparsity-preserving
  (unlike `StandardScaler`, which would densify a 33,639-column sparse
  matrix and blow up memory). After scaling: Naive Bayes jumped to F1 ≈ 0.94,
  and LinearSVC converged cleanly with no warnings. Lesson: feature scale
  matters even for "just concatenate the features" pipelines, and it's easy
  to miss when each feature type looks fine in isolation.
- **Naive substring keyword matching was a real bug, not just a style
  nit**: the first version matched keywords with plain `if kw in text`,
  which meant a bare `"dito"` (the DITO Telecom brand) matched the Tagalog
  word *dito* ("here") in completely ordinary sentences. Fixed by (a)
  disambiguating brand tokens that collide with common words into
  multi-word phrases (`"dito telecom"`, `"three mobile"`) and (b) switching
  every keyword to a word-boundary-aware regex (`\bups\b`) so short courier
  codes like "ups" don't fire inside unrelated words like "backups".
  Covered by `test_keyword_matching_respects_word_boundaries`.
- **A "false negative" that probably isn't the model's fault**: one missed
  spam message — *"Sorry I missed your call let's talk when you have the
  time. I'm on 0709..."* — reads exactly like an ordinary text and got
  P(spam) = 0.02. It's a UCI-labeled premium-rate callback scam (a
  follow-up text after a subscription trap), which is a genuinely hard
  case — even a human reading it cold wouldn't flag it without the earlier
  message in the thread. This is a labeling/context limitation of the
  dataset, not something more feature engineering fixes.
- One PH-augmentation message was also missed: a pure-Tagalog OTP-phishing
  line with no URL and no English urgency phrasing (`"Para ma-secure ang
  account mo, i-send ang OTP..."`, P(spam) = 0.41). The `otp` keyword fired,
  but the urgency-word list is English-only, so Tagalog-phrased urgency
  gets no boost from that feature — a real gap, not a fluke. **None** of
  the international-augmentation examples were missed, for comparison.

## Limitations

- Both augmentation sets (95 PH + 82 international messages) are synthetic
  and hand-written by me, not sourced from real, consenting victims'
  inboxes — they encode publicly known scam *templates*, not validated
  real-world traffic at scale. Real smishing evolves fast; this will go stale.
- "International" here means the US/UK/EU/AU/CA patterns I could research
  and verify from public advisories — it is not actually comprehensive
  worldwide coverage (no coverage yet for, e.g., India, most of continental
  Europe's local banks, Latin America, or most of Africa/the Middle East).
  Calling it "international" is aspirational in scope, not a claim of
  global completeness.
- The urgency-word list is English-only, so non-English urgency phrasing
  (Tagalog, or any other language) only gets caught via brand keywords and
  TF-IDF, not the urgency-count feature — see the missed Tagalog OTP example
  above.
- Trained on a fairly small, imbalanced dataset (5,335 messages, 14.0%
  spam). Precision/recall at this scale can be noisy — the CV standard
  deviations (±0.01-0.02 F1) reflect that.
- This is a portfolio/educational project, not a production fraud filter.
  It has no rate limiting, no adversarial robustness testing, and hasn't
  been evaluated against an attacker deliberately trying to evade it.

## Project structure

```
data/raw/                                        UCI dataset + PH/international augmentation CSVs
scripts/build_ph_augmentation_dataset.py         regenerates the PH CSV
scripts/build_international_augmentation_dataset.py   regenerates the international CSV
src/data_loader.py                               load + combine + split all three datasets
src/features.py                                  TF-IDF + handcrafted feature extraction
src/train.py                                      CV model comparison, fit best, save artifacts
src/evaluate.py                                   metrics + false positive/negative analysis
src/predict.py                                    CLI: classify one message, explain why
models/                                           saved vectorizers/scaler/model (joblib) + metadata.json
results/                                          metrics.json, test_predictions.csv
tests/                                            pytest unit + integration tests
```

## How to run

```bash
pip install -r requirements.txt

# regenerate the augmentation datasets (optional, already committed)
python3 scripts/build_ph_augmentation_dataset.py
python3 scripts/build_international_augmentation_dataset.py

# train + compare models, save the best one
python3 -m src.train

# evaluate on the held-out test set + see misclassified examples
python3 -m src.evaluate

# classify a message
python3 -m src.predict "E-ZPass: You have an unpaid toll of $6.99. Pay now: ezpass-tollpay.com"

# run tests
python3 -m pytest tests/ -v
```

## Future work

- Expand both augmentation sets with more scam categories and more
  languages/dialects (Cebuano/Ilocano code-switching; Spanish, French,
  German, Hindi scam templates for genuinely broader international
  coverage).
- Make the urgency-word list multilingual instead of English-only.
- Try a lightweight transformer (e.g. distilled multilingual BERT) and
  compare against the TF-IDF baseline on the same test set — the honest
  question is whether it's actually worth the added complexity/latency
  here, given how well the linear model already does.
- Basic adversarial testing: how much can a spam message be reworded before
  it slips past the classifier?
